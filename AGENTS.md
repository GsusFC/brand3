S337 Investigación de consistencia de datos entre Magnetism Scanner y Brand Audit — ¿usan todos la misma información? (May 22 at 4:41 PM)
**Investigated**: Se examinó el código fuente de los dos flujos del Magnetism Scanner en Brand3: el modo directo por URL (`/magnetism-scanner/analyze`) y el modo desde Brand Audit run (`/magnetism-scanner/from-run`). Se revisaron los archivos `extractor.py` y `magnetism_scanner.py`.

**Learned**: - El Magnetism Scanner directo usa únicamente `WebCollector().scrape(url)`, `markdown_content` (truncado a 8000 chars), screenshot o fallback Playwright, y `visual_semantics`. Es un scan ligero con menos datos que Brand Audit.
    - El Magnetism Scanner desde Brand Audit run reutiliza un snapshot de Brand Audit, pero NO usa el dataset bruto completo — lo compacta en un `evidence_text` mediante `collect_evidences(snapshot)`, seleccionando hasta 80 evidencias.
    - Incluso el modo que parte de Brand Audit no expone todo el dataset al LLM, sino una versión resumida/seleccionada.
    - Los dos caminos tienen calidad de datos diferente: directo = menos datos, desde-audit = más datos pero compactados.

**Completed**: Diagnóstico completo de inconsistencia de datos entre los dos modos del Magnetism Scanner. Se confirmó en código que NO siempre se usa la misma extracción ni la misma cantidad de datos.

**Next Steps**: El equipo está discutiendo una propuesta arquitectural: que el Magnetism Scanner use siempre un "Brand Audit Evidence Packet" como fuente principal, y que el modo URL directo cree primero ese packet o avise explícitamente que es un scan ligero.
