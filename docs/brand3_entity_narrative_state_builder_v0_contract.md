# Brand3 EntityNarrativeState Builder v0 Contract

Date: 2026-05-17

Scope: specification only. No code, builder, prompts, scoring, generation, rendering, persisted payload format, Visual Signature code, report audits, fixtures, or runtime behavior were changed.

## Executive Contract

The offline `EntityNarrativeState` builder v0 should be a deterministic composition-state compiler.

It should not be:

- a prose generator,
- a strategist,
- a scoring layer,
- an editorial judge,
- a prompt rewrite,
- a runtime gate,
- a Visual Signature integration.

Its job is to compile already-measured narrative diagnostics into a stable state object that can describe composition pressure before any future prompt or runtime decision.

The builder is justified because Phase 2 showed the same core pattern across LaunchDarkly, Iris, and Watermelon:

```text
good evidence collection
but uneven finding-level evidence binding
plus repeated safe attribution and corroboration caveats
```

The builder should therefore represent evidence-binding, repetition budgets, source-ownership pressure, entity/surface ambiguity, and review-gated contradiction candidates. It must not infer strategic intent or brand psychology.

## Input Contract

### Required: `report_narrative`

The builder must accept an existing persisted `report_narrative`-shaped payload as a plain dictionary.

Expected usable surfaces:

- brand or entity name if present,
- report or run metadata if present,
- synthesis text if present,
- tensions text if present,
- dimension findings,
- finding titles,
- finding observations,
- finding implications,
- finding `typical_decision` values,
- finding evidence URLs.

The builder must treat this payload as source material, not as truth.

It may count and summarize structures already present in the payload. It must not rewrite payload prose.

### Required: payload-level Narrative Harness diagnostic

The builder should accept the payload-level diagnostic generated by the offline Narrative Harness.

Expected usable metrics:

- status,
- warning count,
- finding count,
- findings without evidence URLs,
- repeated sentence openings,
- generic strategic filler count,
- unsupported prescription count,
- missing evidence URL metrics,
- safe attribution phrase counts,
- safe attribution total,
- observation repetition family counts,
- fallback evidence-opening repetition,
- external corroboration caveat repetition,
- generic `teams in this position typically` count.

These metrics should be the primary source for deterministic budgets.

### Required: render-aware Narrative Harness diagnostic

The builder should accept the render-aware diagnostic generated from rendered HTML or rendered text.

Expected usable metrics:

- visible render status,
- visible repeated sentence openings,
- visible safe attribution total,
- visible generic filler,
- visible evidence chip or link count,
- visible `Decision space` count,
- visible `Teams in this position typically` count,
- visible `The brand...` count,
- suppressed-by-rendering metrics,
- still-visible risk count.

Render-aware metrics should not replace payload metrics. They should distinguish stored narrative risk from visible report risk.

### Optional: snapshot or base dossier metadata

The builder may accept snapshot, base dossier, or run metadata when already available.

Allowed uses:

- run id,
- URL,
- brand name,
- data quality,
- score summary,
- evidence total,
- owned evidence total,
- third-party evidence total,
- context coverage,
- context confidence,
- related domains or surfaces if explicitly collected.

If upstream metadata does not provide explicit related-surface information, the
builder must leave related surfaces empty or marked `unknown`. The preferred
upstream field is `entity_resolution.related_surfaces`; the builder mirrors it
into `entity_aliases.observed_related_surfaces` only for legacy compatibility
with older fixtures and consumers.
The builder must not infer related surfaces from search results, name
similarity, or unreviewed evidence URLs.

Forbidden uses:

- inferring strategic intent,
- inferring market archetype,
- inferring audience psychology,
- converting score into narrative quality,
- treating Visual Signature signals as runtime inputs.

If snapshot metadata is absent, fields depending on it must remain `unknown`, `not_available`, or manually unset.

## Output Contract

The builder should return a JSON-like dictionary with a stable top-level shape.

Recommended top-level keys:

```json
{
  "version": "entity_narrative_state.v0",
  "status": {},
  "metadata": {},
  "inputs": {},
  "state": {},
  "derivation": {},
  "limitations": []
}
```

### Required fields

These fields should always exist.

#### `status`

Purpose: keep the artifact visibly offline and non-runtime.

Required values:

- `experimental: true`
- `offline_only: true`
- `runtime_enabled: false`
- `used_by_scoring: false`
- `used_by_prompts: false`
- `used_by_rendering: false`
- `persisted_report_narrative: false`
- `llm_generated: false`

#### `metadata`

Purpose: describe provenance and entity identity without overclaiming.

Required fields:

- `brand`
- `url`
- `created_from`
- `created_at` or `generated_at`
- `case_family` when known

If brand or URL is unavailable, use `unknown` rather than inventing it.

#### `inputs`

Purpose: record which artifacts fed the state.

Required fields:

- `report_narrative_payload`
- `payload_diagnostic`
- `render_aware_diagnostic`
- `snapshot_or_base_dossier`

Each should include at least:

- `available`
- `source_id` or `path`
- `notes`

#### `state.primary_entity_signal`

Purpose: identify the audited entity anchor without resolving ambiguity beyond evidence.

Required fields:

- `label`
- `confidence`
- `supporting_sources`
- `uncertainty`
- `requires_human_review`

Allowed values:

- `confidence`: `high`, `medium`, `low`, `unknown`

If no explicit source identifies the entity, `label` must be `unknown`.

#### `state.entity_aliases`

Purpose: record related surfaces without implying verified equivalence.

Required fields:

- `primary`
- `observed_related_surfaces` (legacy compatibility alias mirrored from the packet field)
- `needs_review`
- `confidence`

The builder may mirror `entity_resolution.related_surfaces` into `observed_related_surfaces` for compatibility only when explicit surfaces are present. It must not infer corporate ownership from name similarity alone.
`entity_resolution.related_surfaces` remains the canonical input.

#### `state.owned_claim_density`

Purpose: summarize owned/self-description pressure.

Required fields:

- `level`
- `safe_attribution_total`
- `phrase_counts`
- `source`

Allowed `level` values:

- `inactive`
- `low`
- `moderate`
- `high`
- `unknown`

This field must be derived from safe attribution metrics when available.

#### `state.repeated_opener_budget`

Purpose: summarize repeated opener pressure.

Required fields:

- `status`
- `max_same_opening`
- `tracked_openings`
- `observed_counts`
- `source`

Allowed `status` values:

- `inactive`
- `within_budget`
- `over_budget`
- `unknown`

#### `state.fallback_language_budget`

Purpose: distinguish real fallback mode from fallback-like repetition inside good-data runs.

Required fields:

- `mode`
- `fallback_mode`
- `fallback_like_repetition`
- `phrase_counts`
- `source`

Allowed `mode` values:

- `inactive`
- `fallback_mode`
- `fallback_like_repetition`
- `unknown`

#### `state.evidence_url_coverage`

Purpose: make local finding-level evidence binding explicit.

Required fields:

- `finding_count`
- `findings_without_evidence_urls`
- `coverage_level`
- `visible_evidence_link_count`
- `affected_dimensions`
- `source`

Allowed `coverage_level` values:

- `strong`
- `mixed`
- `weak`
- `unknown`

Missing evidence URLs must be represented as a coverage metric, not as an absolute editorial failure.

#### `state.decision_space_mode`

Purpose: record whether `typical_decision` should be visible, hidden, or considered not applicable in future experiments.

Required fields:

- `mode`
- `generic_decision_count`
- `visible_decision_space_count`
- `render_suppression_observed`
- `advisory_only`

Allowed `mode` values:

- `show`
- `hidden_generic`
- `compressed_candidate`
- `not_applicable_empty`
- `unknown`

This field is advisory only. It must not control rendering in v0.

### Optional fields

These fields may exist when source data supports them.

#### `state.source_ownership_summary`

Purpose: summarize owned, third-party, technical, fallback, and unknown evidence source pressure.

Required when present:

- `method`
- `owned_or_self_description`
- `third_party_or_external_assessment`
- `technical_or_configuration`
- `uncited_or_missing_evidence_url`

Allowed `method` values:

- `metrics_from_snapshot`
- `manual_estimate`
- `unknown`

If no formal source classifier exists, this field must use `manual_estimate` or `unknown` and carry confidence notes.

#### `state.attribution_budget`

Purpose: describe whether owned-claim attribution repetition needs consolidation.

Required when safe attribution is moderate or high.

Required when present:

- `status`
- `max_repeated_safe_attribution`
- `observed_safe_attribution_total`
- `global_caveat_preferred`
- `source`

Allowed `status` values:

- `inactive`
- `within_budget`
- `over_budget`
- `unknown`

#### `state.corroboration_caveat_budget`

Purpose: describe repeated external corroboration caveat pressure.

Required when external corroboration caveat repetition exceeds the configured warning threshold.

Required when present:

- `status`
- `observed_caveat_total`
- `global_caveat_preferred`
- `source`

Allowed `status` values:

- `inactive`
- `within_budget`
- `over_budget`
- `unknown`

### Conditional and review-gated fields

These fields should never be promoted to facts without explicit evidence.

#### `state.primary_tension`

Purpose: hold a candidate entity-level composition tension.

Required rules:

- optional,
- `requires_human_review: true` unless directly sourced from an explicit payload field,
- `source` must be `manual_synthesis`, `payload_tension`, or `unknown`,
- confidence must be present.

The builder v0 should normally leave this field as `unknown` or omit it unless the payload already contains explicit synthesis/tension material that can be copied without expanding meaning.

#### `state.contradiction_candidates`

Purpose: record possible stated-claim versus observed-signal conflicts.

Each item must include:

- `stated_claim`
- `observed_signal`
- `supporting_sources`
- `confidence`
- `requires_human_review`

The builder must not create contradiction candidates from aesthetics, scores, or name similarity alone.

#### `state.compression_candidates`

Purpose: mark findings that may need compression or demotion in future editorial experiments.

Required rules:

- every item must be `suggested_only: true`,
- every item must include a deterministic reason,
- no item may include rewritten prose,
- no item may imply runtime behavior.

### Fields derived only from metrics

These fields must come from harness diagnostics or direct counts:

- `owned_claim_density.safe_attribution_total`
- `owned_claim_density.phrase_counts`
- `repeated_opener_budget.observed_counts`
- `fallback_language_budget.phrase_counts`
- `evidence_url_coverage.finding_count`
- `evidence_url_coverage.findings_without_evidence_urls`
- `evidence_url_coverage.visible_evidence_link_count`
- `decision_space_mode.generic_decision_count`
- `decision_space_mode.visible_decision_space_count`
- `attribution_budget.observed_safe_attribution_total`
- `corroboration_caveat_budget.observed_caveat_total`

### Fields that must remain unknown unless source data is explicit

These fields must be `unknown`, absent, or review-gated if not explicit:

- `primary_entity_signal.label`
- `entity_aliases.observed_related_surfaces`
- `source_ownership_summary` counts when no source classifier or metadata exists,
- `primary_tension.summary`,
- `contradiction_candidates`,
- relationship between related domains,
- ownership of adjacent surfaces,
- strategic intent,
- market position intent,
- audience psychology,
- brand archetype,
- narrative quality score.

## Derivation Rules

### Deterministic counts

The builder may deterministically count:

- findings,
- findings with and without evidence URLs,
- evidence URL totals,
- visible evidence chip or link totals,
- repeated opener phrase counts,
- safe attribution phrase counts,
- fallback evidence phrase counts,
- corroboration caveat phrase counts,
- generic decision-space phrase counts,
- visible suppressed decision-space counts when provided by render-aware diagnostics.

### Deterministic level mapping

The builder may map counts into coarse levels.

Recommended v0 defaults:

- `0`: `inactive`
- `1-2`: `low`
- `3-7`: `moderate`
- `8+`: `high`

For evidence URL coverage:

- no finding count: `unknown`
- 80 percent or more findings with evidence URLs: `strong`
- 40 percent to 79 percent: `mixed`
- below 40 percent: `weak`

These thresholds are diagnostic defaults, not editorial truth.

### Estimated fields

The builder may estimate only when the source method is explicit.

Allowed estimated fields:

- source ownership buckets,
- case family,
- primary entity confidence,
- related-surface confidence.

Every estimate must include:

- `method`,
- `confidence`,
- `notes`.

### Unknown fields

The builder must preserve uncertainty rather than filling fields for completeness.

Use `unknown` when:

- no explicit URL or entity metadata exists,
- a tension would require synthesis beyond payload text,
- adjacent surfaces are name-similar but not evidence-linked,
- source ownership cannot be counted,
- a contradiction would require interpretation.

### Never infer

The builder must never infer:

- strategic intention,
- desired audience psychology,
- cultural authority,
- premium positioning,
- founder intent,
- market maturity,
- visual confidence as evidentiary confidence,
- contradiction from score difference alone,
- entity ownership from domain or brand-name similarity alone,
- future recommendations,
- report prose rewrites.

## Field-to-Metric Mapping

| Output field | Primary source | Derivation |
|---|---|---|
| `owned_claim_density` | payload diagnostic | safe attribution total and phrase counts |
| `repeated_opener_budget` | payload and render-aware diagnostics | repeated openings and visible repeated openings |
| `fallback_language_budget` | observation repetition family metrics | fallback evidence-opening counts |
| `evidence_url_coverage` | payload diagnostic and render-aware diagnostic | finding count, missing URLs, visible evidence links |
| `decision_space_mode` | payload and render-aware diagnostics | generic `typical_decision` count and visible `Decision space` count |
| `attribution_budget` | payload diagnostic | safe attribution total above threshold |
| `corroboration_caveat_budget` | observation repetition family metrics | external corroboration caveat repetition count |
| `source_ownership_summary` | snapshot/base dossier metadata | owned/third-party/technical counts if explicit |
| `primary_entity_signal` | report metadata, URL, payload | explicit brand and URL only; no inferred ownership |
| `entity_aliases.observed_related_surfaces` | snapshot/base dossier metadata, evidence URLs | explicit surfaces only |
| `primary_tension` | payload synthesis/tensions or manual review | review-gated; no automatic invention |
| `contradiction_candidates` | explicit stated claim plus explicit observed signal | review-gated; evidence required |
| `compression_candidates` | diagnostics | suggested-only items based on repeated generic fields |

## Target Fixtures And Cases

### Builtwith

Primary purpose:

- owned-claim repetition,
- entity ambiguity,
- corroboration caveat repetition,
- missing evidence URLs,
- generic decision-space suppression.

Expected builder behavior:

- activate `owned_claim_density`,
- activate `attribution_budget`,
- activate `corroboration_caveat_budget`,
- activate `evidence_url_coverage`,
- mark entity ambiguity as review-needed,
- avoid strategic claims about Kit or BuiltWith intent.

### Netlify

Primary purpose:

- fallback evidence-opening repetition,
- simpler entity state,
- inactive owned-claim pressure,
- inactive contradiction pressure.

Expected builder behavior:

- activate `fallback_language_budget`,
- keep `attribution_budget` inactive,
- keep `corroboration_caveat_budget` inactive if metrics are zero,
- keep `contradiction_candidates` empty,
- avoid manufacturing a primary tension.

### LaunchDarkly

Primary purpose:

- high-evidence control case that still shows evidence-binding issues.

Expected builder behavior:

- show good global evidence context if snapshot metadata is available,
- show mixed finding-level evidence URL coverage,
- activate safe attribution and corroboration caveat budgets,
- avoid treating a strong evidence base as proof of coherent findings.

### Iris

Primary purpose:

- strong visual/perceptual surface pressure with mixed entity corroboration.

Expected builder behavior:

- activate owned-claim and caveat budgets,
- record observed related surfaces only when explicit,
- mark related-surface interpretation as review-needed,
- keep visual strength separate from evidentiary confidence.

### Watermelon

Primary purpose:

- ecosystem and composition ambiguity.

Expected builder behavior:

- record explicit observed related surfaces,
- flag entity/surface review pressure,
- activate evidence-binding and caveat budgets,
- keep contradiction candidates review-gated,
- expose lexical diagnostic limits in notes when relevant.

## Expected Tests For Future Implementation

The implementation should include tests for these invariants.

### Stable output shape

Given a minimal valid payload and diagnostics, the builder returns:

- `version`,
- `status`,
- `metadata`,
- `inputs`,
- `state`,
- `derivation`,
- `limitations`.

### No strategic claims invented

Given diagnostics with repeated caveats but no explicit strategic claim, the builder does not create:

- strategic intent,
- brand archetype,
- audience psychology,
- market-position interpretation,
- contradiction candidate.

### Good-evidence cases do not force false tensions

Given LaunchDarkly-like evidence totals and warning diagnostics, the builder may show evidence-binding pressure but must not force `primary_tension` unless explicit source text exists.

### Multi-surface cases activate packet-related surfaces

Given Iris-like or Watermelon-like explicit related domains, the builder populates `entity_resolution.related_surfaces`, mirrors them into `observed_related_surfaces` for compatibility, and sets `needs_review: true` without claiming verified equivalence.

### Missing evidence URLs become coverage metrics

Given findings without evidence URLs, the builder updates `evidence_url_coverage` but does not mark the report as editorially invalid.

### Inactive budgets remain inactive

Given Netlify-like zero safe attribution and zero corroboration caveat counts, the builder keeps `attribution_budget` and `corroboration_caveat_budget` inactive or absent.

### Review-gated fields are not promoted to facts

Given possible tension or contradiction text, the builder sets `requires_human_review: true` unless the source explicitly states the relationship.

### Render-aware suppression remains diagnostic

Given render-aware diagnostics where generic `Decision space` is suppressed, the builder records suppression but does not change rendering or payload content.

## Explicit Non-Goals

Do not implement:

- runtime integration,
- scoring changes,
- prompt changes,
- renderer changes,
- Visual Signature integration,
- report payload mutation,
- LLM calls,
- automatic contradiction reasoning,
- automatic recommendation generation,
- prose rewrites,
- narrative quality scoring.

## Readiness Decision

The v0 contract is ready for a future offline builder implementation.

The builder should start with deterministic metrics and conservative unknowns. It should compile composition state from existing diagnostics, not generate analysis.

Runtime use remains out of scope until the offline builder has been tested across Builtwith, Netlify, LaunchDarkly, Iris, and Watermelon and shown to preserve uncertainty without inventing strategic meaning.
